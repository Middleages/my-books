## 앱 하나를 띄운 다음에 생기는 질문

Docker로 웹앱 하나를 실행했습니다. 앱이 늘어나자 설정 파일의 위치, 다시 시작하는 방법, 새 버전을 교체하는 순서를 기억하기 어려워집니다. 이 책은 그 운영 일을 **누가 맡고, 어떤 상태를 보고 움직이는지** 이해하는 데서 시작합니다.

<ImagePrimer />

쿠버네티스(Kubernetes)는 컨테이너로 실행되는 앱의 배치와 상태 유지를 관리하는 시스템입니다. k3s는 그 공통 API와 개념을 간결한 구성으로 제공하는 배포판입니다. 둘을 서로 다른 용도의 대체 제품으로 외우지 않습니다.

## 이 책에서 해 볼 일

가상의 `study-web`을 기준으로 실행·연결·설정·데이터의 위치를 따라갑니다. 처음에는 단일 Linux VM을 생각합니다. 한 VM에 모든 역할이 있어도 클러스터라고 부를 수 있지만, VM 장애까지 버티는 구성이 되는 것은 아닙니다.

- **지금 공개:** 01 운영 책임과 복구의 범위, 02 클러스터의 역할과 두 가지 경로, 03 원하는 상태와 Pod, 04 Service와 앱 발견, 05 외부 요청과 TLS, 06 설정과 비밀정보, 07 저장 수명, 08 자원 배치와 실행 한도, 09 상태 검사, 10 단계별 배포와 되돌리기, 11 Helm 배포 묶음, 12 증거 기반 진단.
- **후속 계획:** 설치·복구·폐쇄망 선택 실습 부록. 아직 제공되지 않는 후속 범위입니다.
- **완독 목표:** 내 앱이 어디에서 실행되고 어떻게 연결되는지 설명하고, 작은 변경을 배포하며 멈춘 구간의 증거를 찾기.

## 설치 없이 시작하고, 실습은 선택하기

| 경로 | 필요한 것 | 지금 가능한 것 |
| --- | --- | --- |
| 브라우저 학습 | 이 페이지 | 그림·단계 재생·조건 비교. 실제 서버에 접속하지 않음 |
| 선택 실습 | 별도의 일회용 Linux VM | 이번에는 환경 계약만 정의. 설치·첫 배포 묶음은 후속 부록에서 제공 |

개발 PC마다 k3s를 설치할 필요는 없습니다. 로컬 프로세스나 Compose로 개발하고 별도 실습 클러스터에서 확인할 수 있습니다. kind는 컨테이너 기반 학습·테스트 선택지지만, 이 책의 선택 실습 기본 경로는 **일회용 Linux VM의 k3s**입니다. WSL·Docker Desktop·macOS는 네트워크와 파일 경로가 다르므로 동일하게 검증됐다고 가정하지 않습니다.

IP·포트·DNS·TLS·프록시가 낯설면 [네트워크 교재](#/network)를 함께 보세요. 기존 프록시나 외부 DB를 모두 갈아엎는 것을 출발 조건으로 삼지 않습니다.

**읽는 방법:** 그림에서 경계를 찾고 → 결과를 예상하고 → 한 단계씩 진행하고 → 조건 하나만 바꿔 비교하세요. 움직임 없이 읽는 전체 단계 설명도 제공합니다.

문서 기준은 Kubernetes v1.35 개념이며, 선택 실습 후보는 k3s `v1.35.9+k3s1`입니다. 2026-10-18 공식 문서를 확인했지만 실제 클러스터 설치·이미지 실행은 수행하지 않았습니다. 학습 화면의 v1/v2는 배포 가능한 이미지 태그가 아닙니다.
