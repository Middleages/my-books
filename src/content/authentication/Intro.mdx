첫 장은 인증과 인가의 두 문을 통과합니다. 두 번째 장은 브라우저 쿠키와 서버 세션 기록을 떨어뜨려 봅니다. 쿠키를 가지고 있어도 서버 기록이 만료되거나 다른 인스턴스에 없으면 로그인 상태를 이어 갈 수 없습니다.

## 작은 가상 문서함에서 시작합니다

가람과 누리는 합성 인물이고 a.example.test·b.example.test는 연결하지 않는 가상 주소입니다. 실제 계정·비밀번호·쿠키·토큰을 입력하지 않습니다. 화면의 SIM-SESSION-A도 로그인에 쓸 수 없는 라벨입니다. 이 웹페이지가 실제로 인증 서버가 되거나 안전한 로그인 구현을 제공하는 것은 아닙니다.

브라우저를 사용하는 기본 경험이면 시작할 수 있습니다. 03–04장에서는 브라우저의 전송·처리·응답 읽기와 JWT의 내용·신뢰를 나눠 봅니다. 05–06장에서는 OAuth 권한 위임과 OIDC code 왕복을 연결합니다. 07–08장에서는 여러 앱의 독립 세션과 역할·객체 권한을 비교합니다. 09–10장에서는 만료·갱신·로그아웃과 React/FastAPI 구조의 신뢰 경계를 비교합니다. 현재 읽을 수 있는 본문은 소개와 01–10장입니다. 폐쇄망 운영과 종합 진단은 이후 범위입니다. SSO는 한 번 확인한 신원을 여러 앱에서 활용하는 설계와 관계있지만, 각 앱의 권한과 세션이 자동으로 하나가 되는 것은 아닙니다. 이 구분을 먼저 익히겠습니다.

## 조작하고, 멈추고, 확인합니다

먼저 결과를 예측한 뒤 한 단계씩 문을 열어 보세요. 처음부터 재생할 필요는 없습니다. 정적 표에도 같은 정책과 상태가 남습니다. 실제 서비스의 보안은 비밀번호 검증·암호화·TLS·브라우저 정책·서버 운영을 포함하므로 이 합성 실험만으로 검증됐다고 할 수 없습니다. 실제 SSO 연결과 운영 설정은 여기서 실행하지 않습니다.
