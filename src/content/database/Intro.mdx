## 저장됐는데, 왜 틀릴까요?

작은 상점의 웹앱을 만들었습니다. 주문은 저장되지만 두 사람이 마지막 상품을 동시에 주문하면 어떻게 될까요? 고객별 주문을 조회했는데 건수가 늘거나, SQL은 금방 끝났는데 화면은 오래 기다리기도 합니다.

이 책은 SQL을 많이 외우기보다 **데이터가 맞아야 하는 약속과 요청이 지나가는 경계**를 이해하는 데 집중합니다. 그림에서 관계를 찾고, 조건을 하나씩 바꾸며, 무엇을 더 확인해야 하는지 판단합니다.

## 같은 상점으로 이어지는 질문

가상 문구 상점 `study-shop`의 고객·상품·주문·주문 항목을 사용합니다. 고객 이름과 주문 금액은 합성 자료이며 실제 계정이나 결제와 연결하지 않습니다. 이 책의 ‘주문 확정’은 재고를 예약한 상태이지 결제 성공이나 회계상 매출을 뜻하지 않습니다.

- **지금 공개:** 01 파일 다음에 데이터베이스, 02 표 사이의 약속.
- **이어 쓸 내용:** 조회와 인덱스, 트랜잭션과 동시 실행, 연결 풀과 실행계획, 내구성과 복구, 스키마 변경과 종합 진단.
- **완독 목표:** 데이터가 틀리거나 조회가 느릴 때 어떤 관계가 깨졌고 어느 증거를 확인해야 하는지 설명하기.

## 설치 없이 배우기

본문의 그림과 단계 실험은 브라우저 안의 **교육용 모델**입니다. PostgreSQL 서버나 SQL 엔진이 아니며 외부 DB에 접속하지 않습니다. 기본 화면에서 예상한 뒤 ‘다음 단계’를 누르고, 조건을 바꿔 비교하세요. 재생을 기다리지 않아도 모든 단계를 읽을 수 있습니다.

구체적인 SQL 의미는 **PostgreSQL 18 공식 문서**를 기준으로 설명합니다. Microsoft SQL Server(MSSQL)에서 달라지는 부분은 필요한 장의 짧은 상자로 구분합니다. 같은 이름의 기능이라도 모든 제품의 내부 동작이 같지는 않습니다.

실제 SQL을 확인하는 일회용 DB 실습은 선택 경로로 별도 정리할 예정입니다. 지금은 실제 PostgreSQL 설치·SQL 실행·백업 복구를 검증한 상태가 아닙니다. 운영 DB나 실제 비밀번호를 입력할 필요도 없습니다.

## 먼저 알면 도움이 되는 것

웹 요청이 앱 서버에 도달한다는 정도면 시작할 수 있습니다. 주소·포트·TLS가 낯설다면 [네트워크 교재](#/network)를 함께 읽어도 좋습니다. Kubernetes를 설치하거나 익혀야만 이 책을 읽을 수 있는 것은 아닙니다.

읽은 뒤에는 ‘정답 숫자’보다 이유를 말해 보세요. **어떤 값이 같아야 하고, 어디까지 보장되며, 어떤 조건에서 결론이 달라지는가?** 이 세 질문이 책 전체에 이어집니다.
