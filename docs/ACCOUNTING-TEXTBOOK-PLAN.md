## 1. 목적과 학습 도착점

**이익이 나는데 왜 현금이 부족할까?**

비전공 성인이 작은 회사의 거래를 따라가며 매출·비용·자산·부채·자본·현금흐름이 서로 어떻게 연결되는지 설명하는 책이다. 분개 암기보다 **어떤 사건이 발생했고, 어떤 권리·의무가 생겼으며, 어느 기간의 성과와 언제의 현금에 반영되는가**를 먼저 묻는다. 복식부기는 그 관계를 빠뜨리지 않는 기록 장치로 소개한다.

읽은 뒤 할 수 있어야 할 일:

1. 회사와 소유주의 경계를 정하고, 출자·차입·매출을 구별한다.
2. 한 거래가 둘 이상의 장부 항목을 바꾸는 이유와 자산 = 부채 + 자본을 설명한다.
3. 대금 수령·지급일과 수익·비용 인식 시점을 구별한다.
4. 매입한 재고 중 팔린 부분, 남은 부분과 매출원가를 연결한다.
5. 외상매출·재고·외상매입·선급/미지급의 변화가 영업 현금에 미치는 방향을 설명한다.
6. 설비 취득·감가상각, 차입 원금·이자, 출자·배당을 서로 다른 사건으로 읽는다.
7. 같은 기간·같은 회사의 세 보고서를 연결하고 이익과 현금의 차이를 항목별로 재구성한다.
8. 비율이나 문서 한 줄로 회사의 안전성·사기 여부·투자 가치를 판정하지 않고 필요한 추가 근거를 고른다.

**제외:** 세무 신고·법인세 산정·법정 장부 작성 대행·회계 자격시험 전 범위·공시 서식 완전 재현·개인별 회계 자문·사업계획 추천·기업가치/주가 예측·실제 종목 추천. 연결 제거, 금융상품 측정, 리스, 외화, 이연법인세, 퇴직급여, 사업결합, 재평가, 복잡한 수익 계약과 원가배부는 존재와 추가 확인 이유까지만 다룬다. 실제 회사·거래처·계좌·직원 정보 업로드와 외부 저장/신고/은행 연동은 추가하지 않는다.

## 4. 공통 사례: 가상 상품판매 회사 ‘작은책상’

### 4.1 기간·경계·단위

완제품 문구를 매입해 판매하는 **가상 독립 회사**다. 제조 회사가 아니므로 제조간접원가 배부를 숨겨 넣지 않는다. 상품은 한 종류, 기본 매입단가 3·판매단가 5, 수량은 개, 금액은 **가상 화폐단위**다. 실제 기업·한국 원화 시세·세율·평균 업계 수익률을 뜻하지 않는다.

- 한 관찰기간은 가상의 30일인 M1이다. M0 말 = M1 기초, M1 말 = M2 기초로 연결한다. 현실 월력·실제 결산연도와 구별한다.
- 기본값은 세금·환율·할인·반품·재고손실·대손·리스·거래비용·기타포괄손익이 없는 교육 모형이다. 생략을 0세율·면세·회수 보장이라는 실제 제도로 설명하지 않는다.
- 현금과 현금성자산을 더 넓게 다루는 실제 공시와 달리 여기서는 사용 제한 없는 현금만 존재한다. 자동 당좌차월·차입은 없다.
- 대표 사례는 상계 없는 단일 회사이며 연결재무제표가 아니다. ‘작은 회사’라는 이유로 K-IFRS나 IFRS for SMEs의 적용 대상이라고 단정하지 않는다.
- 장마다 같은 회사를 보되, 초기 장의 일부 사건만 다룬 **발췌 실습**과 09–10의 **M1 전체**를 표시한다. 발췌 결과를 전체 월말 결산으로 부르거나 아직 배우지 않은 항목을 몰래 빼서 전체 합계처럼 보이지 않는다.
- 03의 계약, 05의 원가, 07의 설비 가정은 인식 조건을 충족한 제한적 예시다. ‘송장 작성 = 수익’, ‘현금 지급 = 비용’ 같은 만능 규칙을 만들지 않는다.

| 기말 현금 / 매출채권 / 재고 / 선급비용 / 유형자산 장부금액 | 225 / 240 / 60 / 40 / 230 | 현금 원장 / 400−160 / 20×3 / 60−20 / 240−10 |
| 자산 합계 | 795 | 225+240+60+40+230 |
| 차입금 / 매입채무 / 미지급비용 | 280 / 90 / 20 | 200+100−20 / 300−210 / 60−40 |
| 부채 합계 / 납입자본 / 이익잉여금 / 자본 합계 | 390 / 350 / 55 / 405 | 280+90+20 / 300+50 / 65−10 / 350+55 |
| 등식 | 795 = 390+405 | 자산과 청구권 양쪽은 같은 회사의 두 관점 |
| 영업 현금흐름(직접 집계) | −150 | 고객160−매입대금210−인적 서비스40−선지급60 |

**현금흐름 분류 가정:** 본 교육 모형에서는 지급이자와 지급배당을 재무활동에 둔다. 실제 보고서는 적용 기준·기간·사업 유형·정책을 확인한다. 이 가정을 장부/표/그림/출처 옆에서 한 번에 읽을 수 있게 하고 ‘이자는 늘 영업’ 또는 ‘모든 기업에서 늘 재무’라고 일반화하지 않는다.

이익 65에서 영업 현금으로의 **교육용 조정 다리**는 `65+감가상각10+재무 분류 이자5−매출채권 증가240−재고 증가60−선급비용 증가40+매입채무 증가90+미지급비용 증가20 = −150`이다. 영업이익 70에서 시작하면 이자 5를 다시 더하지 않는다. 간접법 조정은 현금을 새로 만드는 거래가 아니라 같은 원장의 재표현이다.

완전한 재무제표가 이 세 장으로 끝난다고 가르치지 않는다. 자본변동표·주석·비교정보·포괄손익 등 적용 기준이 요구하는 구성과 모형이 생략한 항목을 09·12에서 확인한다. 위 표를 IFRS/K-IFRS 완전 준수 재무제표나 제출용 서식으로 표시하지 않는다.

### 4.4 조건 비교와 반례 정본

기본값과 바뀐 입력을 항상 함께 적는다. 기간·단가·인식 사건은 유지하고 현금 시점만 바꾸는 비교부터 시작한다.

- **회수만 변경:** 당기 고객 회수 0/160/400이면 이익은 모두 65, 영업 현금은 −310/−150/+90, 기말 현금은 65/225/465, 매출채권은 400/240/0. 현금+매출채권은 465로 유지된다.
- **재고 더 확보:** 매입 120개·360, 판매 80개와 공급자 지급 210 유지. 재고120·매입채무150, 이익65·영업 현금−150·현금225가 유지된다. **재고 증가가 언제나 즉시 현금을 줄이는 것은 아니다.** 그 추가 매입 60까지 당기에 지급하면 영업 현금−210·현금165·매입채무90이 된다.
- **미지급을 결제:** 인적 서비스 비용60은 유지한 채 지급40→60이면 현금225→205·미지급20→0, 이익은65. 지급 연기는 비용 절약이 아니며 합의된 조건과 연체를 구분한다.
- **다음 기간 회수·결제:** M2의 선택 발췌로 매출채권240 회수와 매입채무90·미지급20 결제만 수행하면 새 매출/비용/이익0, 영업 현금+130, 현금355. M1 값은 다시 쓰지 않는다. 이 발췌는 M2 전체 결산이 아니므로 계속 쓰는 서비스·설비의 M2 비용을 없앤 실제 결산처럼 표현하지 않는다.
- **설비 사용기간 비교:** 같은 지급240·잔존0에서 교육 가정24/48개월이면 M1 감가상각10/5, 모형 이익65/70, M1 현금225는 동일. 내용연수를 늘려 이익을 예쁘게 만드는 조작법이 아니라 합리적 추정과 정책 확인의 필요를 설명한다.
- **현금 부족:** 회수0·공급자 지급300·인적 서비스 지급60을 동시에 계획하면 자금이 모자랄 수 있다. 실제 사건 실행은 부족한 지급 직전 멈추고 미결제 의무를 보존한다. 예정 부족액을 음수 현금/새 차입/지급 완료로 꾸미지 않는다. 미완료 시나리오에 정본 전체 월말표를 붙이지 않는다.

## 5. 장별 설명 장면·상호작용·검증 설계

각 장의 첫 화면에는 역할·시점·기본값과 핵심 차이가 드러난다. 아래의 **관계 → 실제 시각 속성 → 조작 전후 → 공통 모델 → 반례 → 접근성**을 구현 전 재확인한다. 같은 텍스트 카드에서 숫자만 바뀌는 화면이나 긴 로그를 주 설명으로 삼지 않는다.

### A · 01 회사의 돈은 누구의 돈일까

- 목표/질문: 회사 통장 증가만으로 매출을 알 수 있는가? 회사의 자산과 소유주의 개인 자산은 왜 나눌까?
- 장면: 회사 경계 안에 현금·상품·설비, 밖에 고객·공급자·소유주·은행을 역할별 형태로 놓는다. 같은 50의 유입도 **소유주→회사, 은행→회사, 고객→회사**에서 반대편 권리/의무가 다른 선으로 연결된다. 자본을 현금 옆의 추가 자산 주머니로 그리지 않는다.
- 조작/모델: 기초500/200/300에서 출자50·차입50·이미 인식한 채권50 회수의 발췌 사례 전환. 채권 회수 사례는 현금450+채권50=부채200+자본300의 별도 기초를 명시한다. 회사/개인 관점 선택은 정보 경계만 바꾸며 회사 현금을 개인 자산에 중복 합산하지 않는다.
- 반례/검증: 출자·차입은 매출0; 기존 채권 회수도 매출0. 고객 선입금의 상세는03에 맡기고 ‘고객이 보냈으니 매출’이라고 단정하지 않는다. 회사 경계 안팎 화살표와 장부 합계를 테스트한다.
- 모바일/정적: 위아래 회사 경계와 세 외부 경로, 직접 HTML 라벨·전후표. 관점/거래는 버튼과 키보드로 전환하며 움직이지 않는 상태에서도 역할을 읽는다.

### A · 02 한 거래의 두 기록

- 목표/질문: 왜 한 거래의 양쪽 기록이 필요할까? 차변·대변은 각각 좋은 일·나쁜 일을 뜻하는가?
- 장면: 같은 눈금의 **자산 구성 띠 = 부채·자본 구성 띠** 아래에서 선택한 계정 두 곳에 같은 거래 표식이 연결된다. 출자50은 양쪽 합계가 함께 길어지고, 설비240 현금취득은 자산 내부 구성이 이동하되 합계가 유지된다. 차변/대변은 좌우 기록 위치로 소개하며 ‘모든 차변=증가’라고 색칠하지 않는다.
- 조작/모델: 기초→T01→T02→T03 발췌, 한 단계/이전/초기화와 거래 전후 동시 보기. 계정 성격에 따른 차변·대변 영향을 모델로 계산한다. 하나의 사건이 네 줄 이상일 수 있음을 예고하고 거래의 한쪽만 확정된 가짜 불균형 프레임을 실제 장부로 내보내지 않는다.
- 검증/반례: 사건마다 차변합=대변합, 자산=부채+자본, T03 자산합 보존. 차변/대변 합이 맞아도 잘못된 계정이나 빠진 거래까지 발견되는 것은 아니다. 잘못 분류했지만 균형인 예를12로 연결한다.
- 모바일/정적: 양쪽을 세로로 재배치해도 등식 연결을 유지; 계정별 증감표·분개표에 이름과 키보드 포커스. 음수 자본은 절댓값 양의 막대로 숨기지 않는다.

### B · 03 팔았을 때와 받았을 때

- 목표/질문: 주문, 인도, 청구, 회수의 날짜가 다르면 무엇을 언제 기록하는가?
- 장면: 같은 시간축에 **상품 통제 이전 / 받을 권리 / 현금 도착** 세 행. 상품이 회사 경계를 지나 고객에 도착한 시점과 현금이 반대로 이동하는 시점을 분리한다. 고객 선입금은 인도 전 의무 띠로, 외상은 인도 후 권리 띠로 표시한다.
- 조작/모델: 매출400의 현금 선입금/인도 후 회수/다음 기간 회수 고정 시나리오와 마감선. 기본 T06–T07의 인식/회수만 확대한다. 80개 상품의 재고와 매출원가를 함께 인식한 사실은 숨기지 않고 원가 상세 설명은05로 넘긴다. 수행의무가 하나이고 인도 시 통제 이전·회수가능성 등 필요한 조건을 충족한 자체 계약으로 한정한다.
- 검증/반례: 주문만으로 매출 없음; 선입금만으로 매출 없음; 인도 후 매출과 회수의 이중 집계 없음; 기간 경계 바로 전/후. 반품권·설치·검수·대리거래·장기 서비스는 이 모형으로 결정 불가라고 밝힌다.
- 모바일/정적: 세 행을 날짜별 세로 묶음으로 재배치, 인도/청구/입금 표시를 모양으로도 구분. 날짜 선택/단계 버튼, 앞뒤 고정 장면, 같은 기간별 정적 원장.

### B · 04 쓴 때와 낸 때

- 목표/질문: 먼저 낸 서비스대금과 아직 안 낸 기간비용은 왜 서로 다른 자산·부채인가?
- 장면: 선지급60의 권리 띠를 M1/M2/M3 각각20으로 분할하고 M1 사용분만 비용 구역으로 옮긴다. 아래에는 제공받은 인적 서비스60을 비용으로 한 번 세고 지급40/미지급20으로 갈라지는 경로를 둔다. 현금 출금의 화살표와 비용의 기간 구역을 다른 행에 둔다.
- 조작/모델: 관찰월·이미 제공된 서비스·지급시점 전환. T04/T09–T11을 같은 사건 원장에서 읽으며 M1 비용80·지급100·기말 선급40·미지급20을 검산한다. 자산이 있다는 이유만으로 미래 비용이 사라진 것은 아니다.
- 검증/반례: 선급 잔액+누적 사용비용=60, 미지급=인식비용−지급, 3개월 끝 잔액0, 같은 비용 재지급/재인식 방지. 장래 매출에 도움된다는 이유만으로 임의 비용을 모두 자산화하지 않는다.
- 모바일/정적: 월별 세로 분할과 지급/사용 고정 비교, 월0/1/3 표. keyboard·reset·reduced-motion에서도 일부 사용과 남은 권리의 경계가 보인다.

### C · 05 창고에서 비용으로

- 목표/질문: 100개를 샀는데 80개만 팔았다면 매입대금300과 매출원가240은 왜 다른가?
- 장면: 창고의 **100개 수량 타일** 중80개가 판매 경계를 건너면 그 원가240만 비용 구역으로 옮겨지고20개/60은 남는다. 별도 판매대금 띠400과 매출원가 띠240의 차이160을 같은 눈금에서 보여 준다. 타일 개수는 수량이며 크기·이동속도가 이익률인 것처럼 보이지 않게 한다.
- 조작/모델: 판매수량0–매입수량, 추가 매입, 기본 동일단가. 판매 사건은 매출과 원가를 함께 기록한다. 금액은 수량×단가에서 도출하고 외상 지급 여부가 재고 원가를 자동 바꾸지 않는다.
- 짧은 확장: 원가3인50개+원가4인50개 중60개 판매를 FIFO/기간 가중평균으로 비교하면 원가190/210·기말160/140이다. 두 선택 모두 가용원가350을 나누며 이는 정해진 원가배분 정책 비교이지 실제 물건 이동 순서의 단정이 아니다. 정본과 별도 시나리오로 표시한다.
- 반례/검증: 미판매 재고도 훼손·회수가능액 하락 등이 있으면 손실 검토가 필요하다. 원가와 순실현가능가치의 낮은 금액 원칙은 짧은 주석 예로 연결하고 실제 추정 엔진은 만들지 않는다. 판매0/전량/수량 초과 거부·원가 보존·음수 재고 금지·FIFO/가중평균 차이를 검사한다.
- 모바일/정적: 큰 수량은 묶음 타일과 수량 라벨로 정확히 보존, 창고→판매→원가 세로 경로와 재고 수불표. 수량 입력은 화살표키/버튼으로도 가능하다.

### C · 06 장사가 커질 때 묶이는 돈

- 목표/질문: 외상매출·재고·외상매입이 커질 때 현금은 왜 각각 다른 방향으로 움직일 수 있을까?
- 장면: **현금→재고→매출채권→현금**의 영업 순환을 실제 경로로 놓고 공급자의 외상 신용은 옆에서 지급 시점을 늦추는 별도 구간으로 그린다. 금액 막대와 날짜 길이를 같은 눈금처럼 혼용하지 않는다. 바로 아래 같은 월말의 기본/변경 현금·채권·재고·채무를 같은 금액 눈금으로 비교한다.
- 조작/모델: §4.4의 회수0/160/400, 매입100/120, 공급자 지급210/270과 해당 지급일. 기본 매출·원가를 유지한 첫 비교 뒤에만 판매 증가를 다룬다. 좁은 영업운전자금은 `매출채권+재고−매입채무`, 넓은 분석에는 선급/미지급도 포함한다고 정의한다. 일반적 순운전자금 `유동자산−유동부채`와 같은 이름으로 섞지 않는다.
- 검증/반례: 추가 재고60을 전액 외상으로 받으면 그 순간 현금은 그대로, 결제하면60 감소. 더 빨리 회수하면 이익은 그대로·현금 증가. 납기 지연을 무료 자금조달 추천으로 만들지 않는다. 예정 현금 부족과 실제 미결제 장부를 분리하며 늦게 들어온 돈으로 과거 납기 부족을 지우지 않는다.
- 모바일/정적: 순환을 세로 흐름과 지급 우회선으로 재배치. 날짜별 잔액표·미결제 의무·부족 시점 고정 표시. 단계/정지/초기화와 시나리오 버튼으로 드래그 없이 비교한다.

### D · 07 설비를 사고 여러 달 쓰기

- 목표/질문: 현금240을 한 번 내고 여러 달 쓰는 설비에서 감가상각10은 무엇을 뜻하는가?
- 장면: 위쪽 지급일에 현금240 한 번 유출, 아래 사용기간24칸에 상각대상240을10씩 배분. **취득원가240·누계액10·장부금액230**의 포함 관계를 같은 길이로 보인다. 돈이 상각 때마다 은행으로 이동하거나 저축통장에 쌓이는 애니메이션 금지.
- 조작/모델: 사용 가능한 시점, 내용연수24/48개월, 잔존가치0/명시값, 관찰기간. 취득가·지급은 유지하며 상각표만 바뀌는 비교부터 한다. 정액법은 `(취득원가−잔존가치)/사용개월`의 자체 가정이고 사용 가능한 날부터 비용 배분한다. 기본 판매·관리 설비이므로 재고 제조원가에 들어가지 않는다.
- 검증/반례: 당기 현금은 상각법·사용기간만 바꾸어도 같음, 누적상각≤상각대상, 마지막 회차/0개월·잘못된 잔존/취득0 검증. 장부금액은 시장가격이나 매각대금 보장이 아니다. 수선비·손상·교체·처분손익은 구분 이유까지만, 토지를 같은 정액모형에 넣지 않는다.
- 모바일/정적: 긴24칸을 시간축 구간과 월별 표로 표현, 현재월 전후/기초말 고정 비교. 숫자 입력·재생/정지/한 단계·reset 제공, reduced-motion은 기둥/표 변화만 남긴다.

### D · 08 빌린 돈과 맡긴 돈

- 목표/질문: 왜 출자·차입·이익이 모두 현금을 늘리는 같은 거래가 아니며, 원금·이자·배당은 왜 구별되는가?
- 장면: 회사와 소유주/은행 사이에서 **출자와 배당 경로, 차입과 상환 경로**를 분리한다. 현금 띠 바로 옆의 차입 원금 띠·납입자본 띠·이익잉여금 띠를 연결해 원금20/이자5의 다른 도착 지점을 보인다. 부채와 자본을 둘 다 만기 있는 대출로 그리지 않는다.
- 조작/모델: T01/T02/T13–T15를 선택, 같은 현금 유입을 출자50/차입50으로 비교, 상환액·이자와 배당은 구별된 사건. 정본 기말차입280·납입자본350·이익잉여금55. 전후의 본업 이익은 조달 방식만 바꿔 매출로 증가하지 않는다.
- 검증/반례: 차입금 기초+신규−원금=기말, 비용에 원금/배당 없음, 이익잉여금 기초+모형이익−배당=기말. 주주에게 지급할 수 있는 법적 금액·약정 준수·계속기업을 자본잔액만으로 판정하지 않는다. ‘자본이면 공짜 자금’·‘배당은 영업비용’ 금지.
- 모바일/정적: 당사자 세로 관계도, 원금/이자/배당 직접 라벨과 정적 거래표. 키보드로 사건 순서를 이동하며 실행 중 조건 변경은 초기 재계산, 거래 중복 적용 금지.

### E · 09 같은 회사의 세 보고서

- 목표/질문: 한 시점의 재무상태표와 한 기간의 손익·현금흐름표는 어디에서 연결되는가?
- 장면: M1 시작/끝의 **두 시점 기둥** 사이에 M1 손익 띠와 현금흐름 띠를 놓는다. 이익65는 자본 연결로, 현금변화−275는 현금 연결로 정확히 이어진다. 출자50·배당10은 자본 변동의 별도 가지, 설비240과 감가상각10은 서로 다른 가지다. 숫자 위치만 옮기는 장식 선이 아니라 원장 사건 ID를 클릭해 출처를 추적한다.
- 조작/모델: §4.2의 정본 전체/§4.4 회수 시나리오, 보고 시점과 원장 근거 보기. 세 표를 따로 계산하지 않고 같은 계정 잔액·기간 합계·현금 사건에서 만든다. 자본변동 미니표와 주석 목록을 보여 세 표만 완전한 재무제표라는 오해를 방지한다.
- 검증/반례: §4.3 전 항목, 기초/기말 연속성, 영업/투자/재무 합=현금변화, 자본 연결, 같은 회사·기간·단위. 시점이 다른 표나 연결/별도를 섞은 비교는 계산 결과 대신 불일치를 표시한다. 영업이익/세금 제외 모형 이익/포괄손익을 동의어로 쓰지 않는다.
- 모바일/정적: 세 표를 세로로 놓되 연결하는 항목의 짝과 라벨 유지, 표 탭만 숨겨 두어 기억해야 비교하게 하지 않는다. 전후 요약·전체 원장·읽을 수 있는 연결 문장 제공.

### E · 10 이익에서 현금으로 가는 다리

- 목표/질문: 왜 감가상각은 더하고 채권 증가는 빼며 매입채무 증가는 더할까?
- 장면: 65에서 시작하는 **부호 있는 누적 다리**에 +10,+5,−240,−60,−40,+90,+20을 길이 비례로 연결해−150에 도착한다. 바로 아래 실제 영업 입출금160−210−40−60도−150에 도착한다. 현금225와 영업 현금−150은 잔액/흐름이라는 다른 종점에 둔다.
- 조작/모델: 조정 하나씩 펼치기, 정본/전액회수/추가재고/전액지급 비교, 이익65 시작/영업이익70 시작의 교육용 다리 전환. +5는 지급이자를 재무에 둔 분류 조정임을 명시한다. 이자5를 양쪽 시작점에 중복 가산하지 않는다.
- 검증/반례: 직접 집계=간접 다리, 조정 부호·0/음수 변화·같은 눈금·전체현금 연결. 감가상각을 더했다고 현금이 생긴 것이 아니며 적자·영업 현금 양수도 가능하다. `영업 현금−설비 취득`은 필요하면 정의를 적은 보조값−390만 제시하고 표준화된 유일한 FCF·배당가능액·기업가치라고 부르지 않는다.
- 모바일/정적: 세로 누적 다리와 각 조정 전후 값, 0 기준선·음수 방향·직접법 짝을 유지. 가로 잘림/축 포화 없이 전항목 표와 버튼 단계 제공, 정지 상태에서도 조정 이유를 읽는다.

### F · 11 비교 숫자와 그 한계

- 목표/질문: 분자·분모·기간·정책이 달라지면 같은 비율이 왜 다른 뜻이 되는가?
- 장면: 매출400 띠 안의 총이익160(**40%**)과 영업이익70(**17.5%**) 영역을 분리한다. 유동성 비교는 **유동자산565와 유동부채150**의 양을 나란히 두되 즉시 현금225와 받을/팔아야 하는 자산을 형태로 구별한다. 기본 대출280 중40은 보고일 뒤12개월 이내 상환,240은 이후이며 분류 요건 충족을 가정한다. 따라서150=매입90+미지급20+차입 유동분40, 유동비율 약3.7667배다.
- 조작/모델: 회수율/지급시점·재고 비중·차입 만기 분류·비교 기간 전환. 같은 유동비율이라도 현금과 재고 구성/납기표가 다른 반례. 비율 분모0/음수자본에는 정의·해석 경계를 표시한다. 한 달 성과를 설명 없이 연환산하거나 기말 자산을 평균자산인 것처럼 쓰지 않는다.
- 선택 상자(짧은 경영 관점): 회계상 매출총이익과 공헌이익은 동의어가 아니다. **정본과 분리한** 가상 단일상품 사업계획에서 가격5·개당 변동원가3·기간고정비90이면 `이익=(5−3)q−90`, 손익분기45개다. 판매=구입·재고변화0·세금/이자 제외·고정비 불변·관련 범위 가정. q44/45/46, 가격≤변동원가일 때 양의 유한 분기점 없음. 이는 현금 납기/설비 구입을 해결한 자금계획이 아니며 독립 경영관리 교재로 확대하지 않는다.
- 검증/반례: 같은 분모 비교·0·손실·기간 불일치, 만기 변화는 총부채를 바꾸지 않음, 좋은 비율 하나로 안전/저평가/사기 판정 없음. 회전일수·ROE·EBITDA 백과사전식 추가는 제외한다.
- 모바일/정적: 분자/분모 띠를 세로 정렬하고 금액/비율 단위 분리, 납기표·가정표와 같은 모델. 키보드/정적 비교로 장면을 이해할 수 있어야 한다.

### F · 12 기업 자료 함께 읽기

- 목표/질문: 문서의 금액을 어디까지 믿고 무엇을 더 확인해야 하는가?
- 장면: 자체 작성한 가상 주문/인도 확인·청구/입금 내역·재고 수불·설비 사용/상각 주석·차입 만기표·세 보고서의 해당 항목을 **근거 연결선**으로 잇는다. 모양과 라벨로 ‘관찰 자료 / 계산 / 명시한 가정 / 미확인’을 나눈다. 문서가 정답 카드를 증명하는 장식이 아니라 선택한 주장과 근거의 맞음/모자람을 보여 준다.
- 조작/모델: 정상 정본, 회수일 다음 달, 누락된 재고원가, 출자를 매출로 잘못 분류, 서로 다른 기간/연결 범위의 고정 패킷. 오류 패킷은 의도적 오류라는 라벨을 처음부터 붙이고 정본을 덮어쓰지 않는다. 출자를 매출로 분류한 잘못된 장부도 등식은 맞을 수 있음을 보여준다.
- 검증/반례: 영수증 하나로 모든 수익 인식 요건·소유권·회수가능성·법적 배당가능성을 알 수 없다는 이유와 다음 확인 자료 제공. 점수/체크 수로 감사의견·부실·사기·투자 추천을 생성하지 않는다. 원문 근거가 없는 추정은 미확인으로 남긴다.
- 모바일/정적: 주장 선택 후 관련 문서를 가까이 배치하고 근거선/번호 짝을 유지. 전체 근거 대응표와 문서 텍스트를 키보드로 읽으며 hover로만 근거를 보이지 않는다.
- 최종 편집: 소개·01–12의 용어·주석·수치·기간·단위·소스·연결·접근성·시나리오 경계를 전부 점검한다. 넓은 기존 책 회귀는 F에서 수행하되 실행하지 않은 환경은 미검증으로 남긴다.

## 6. 순수 모델·기록·시각화 계약

구현 후보 위치: 본문 `src/content/accounting/*.mdx`, 조작 `src/components/accounting/`, UI 독립 모델 `src/simulations/accounting/*.mjs`와 `.d.mts`, 테스트 `tests/accounting-*.test.mjs`. A에서 필요한 최소 거래/계정 모델을 만들고 배치마다 확장한다. A가 계획 전체의 본문·UI·미공개 기능을 선행 구현하는 근거는 아니다.

- 계정에는 ID·자산/부채/자본/수익/비용 성격·정상잔액 방향·단위가 있다. 사건에는 고유 ID·사건일·인식기간·문서근거·차변/대변 행·현금흐름 분류·가정이 있다. 같은 사건의 중복 적용을 막는다.
- 입력 → 검증한 사건 → 원장 → 시점별 잔액/기간별 성과/현금 사건 → 관찰 프레임 → SVG·표·설명·판정 순서다. 그림의 선·수량·길이·계정 값은 이 프레임만 읽는다. UI에서 별도 잔액·수익·성공 판정을 만들지 않는다.
- 거래는 원장에 원자적으로 적용한다. 학습용 강조 순서를 거래 내부가 실제로 잠깐 불균형해지는 상태로 오해시키지 않는다. 결산 전 수익·비용을 포함한 현재기간 결과와 이익잉여금으로 마감한 값을 동시에 두 번 더하지 않는다.
- 기본 수치는 정수 가상 화폐단위이며 비율/상각의 소수는 내부 정밀값으로 유지한다. 허용 오차와 마지막 배분 잔액 규칙을 정하고 표시 반올림으로 등식·부족·분기점을 판정하지 않는다.
- 과거 프레임은 입력 변경으로 암묵적으로 수정하지 않는다. 시나리오를 바꾸면 시작 상태부터 재계산하고 비교 조건을 표시한다. 재생은 관찰 인덱스만 움직이고 장부 사건을 타이머마다 다시 적용하지 않는다.
- 현금 지급을 실제 수행한 모델이라면 잔액 부족 시 미실행/미결제 상태와 당시 부족을 보존한다. 예정 계획의 부족과 실행 원장을 분리하며 음수 현금을 자동 신용으로 처리하지 않는다.
- 금액 비례 그래프에는 같은 비교 눈금·0선·단위·기간·기준시점을 표시한다. 수량 타일·금액 막대·날짜 길이의 의미를 구분한다. 범위 초과를 클램프해 서로 다른 값을 같은 크기로 보이지 않는다.
- 미지급·선급·감가상각·원가·차입을 가로지르는 원장은 하나로 묶되 모형 밖의 회계 판정까지 일반화하는 범용 ERP·회계 엔진은 만들지 않는다.

필수 불변량:

1. 모든 확정 사건의 차변합 = 대변합. 모든 확정 프레임의 자산 = 부채 + 자본(당기 미마감 결과 포함).
2. 현금 기초+확정 입금−확정 출금=현금 기말; 영업+투자+재무 현금=같은 기간 현금 증감.
3. 재고 기초+매입−매출원가−명시한 별도 손실=재고 기말. 기본 사례에서는 손실0, 수량 음수/초과판매 없음.
4. 매출채권 기초+외상매출−회수−명시한 조정=기말. 회수는 새 매출 아님. 매입채무도 매입과 결제를 한 번씩 반영.
5. 선급 기초+선지급−사용분=기말, 미지급 기초+비용 인식−지급=기말. 자산과 비용/부채와 지급을 이중 집계하지 않음.
6. 유형자산 원가−감가상각누계액=장부금액(손상/처분 없는 기본); 감가상각 자체의 현금0.
7. 차입 기초+차입 실행−원금 상환=기말. 이자는 원금 상환 아님. 납입자본 변화는 매출 아님. 배당은 비용 아님.
8. 자본 기초+출자+모형 이익−배당=기말(기타포괄손익 등 없는 가정). 이익잉여금은 별도 현금 통장 아님.
9. 직접 영업현금 집계 = 명시한 분류/시작점의 교육용 이익-현금 조정. 시작점/이자 분류가 바뀌면 해당 조정도 함께 바뀜.
10. 기간 마감·다음 기간 이동·재생/정지/초기화/반복에서 사건 중복 없음, M1 기록과 M2 발췌의 경계 보존.

## 9. 이번 계획 작업의 완료 경계

이번에는 이 계획·독립 A–F 실행 프롬프트와 상위 시리즈 연결만 만든다. 앱 본문·계정 모델·카탈로그·표지·테스트/verifier·배포 설정은 바꾸지 않는다. 문서 링크·목차/ID·산술·프롬프트의 범위 일치와 `git diff --check`를 확인하고 실행한 검사만 기록한다. 실제 장 구현·브라우저 학습 장면·출판은 후속 요청의 범위다.

문서 검증(2026-10-20): 예약12개/번호01–12/고유 readId, 독립 A–F 프롬프트6개, 상대 링크, T01–T15의 모든 사건 차변·대변 균형과 잔액 등식, 정본 보고서·현금 다리·조건 비교·비율을 독립 산술 검사로 확인했다. 같은 기준 소스에서 전체 `npm test` **891/891**, `npm run build` **321 modules**와 `git diff --check`를 통과했다. 기존 설치 의존성을 사용했으며 `npm ci`를 새로 실행한 기록은 아니다. 문서만 바뀌므로 새 UI/브라우저/게시 검증은 실행하지 않았고, 위 통과는 회계 본문 구현이나 시각 학습 장면의 검증을 뜻하지 않는다.
