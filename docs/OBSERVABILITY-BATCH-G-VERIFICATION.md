- 소개 + 01–12의 순서·ID/readId 유일성과 12개 읽음 분모, future01–12를 대조했다. 소개는 별도 Intro이며 읽음 분모에 추가하지 않았다. 13MDX import 및 상대 링크 대상이 존재한다.
- 01–02: logs/metrics/traces는 서로 대체하지 않으며 Alloy 수집, Loki/Tempo/Mimir 저장, Grafana 조회를 구분한다. 앱 실패와 관측 경로 실패를 같은 성공 표시로 합치지 않는다.
- 03–04: 사건/관측 시각, 중복/필드 제외, counter/gauge 누락 및 원본 duration 분포를 구분한다. unknown을0으로 바꾸지 않는다.
- 05–06: 실제 관측 라벨 조합과 가능한 Cartesian 곱, 동일0–300ms 축의 겹친 span과 부모 관계, 전파 실패와 미수집을 구분한다.
- 07–08: 업무1과 span 수, 프로세스/SDK 경계, 표본 선택과 전달 실험, pending·ACK·유실과 수신 복사본을 분리한다.
- 09–10: 같은 시간창·조건의 분자/분모·원본 percentile, 요청 데이터와 용량 표본, no-data/empty/query-error, 평가 간격과 유지 시간을 구분한다. 알림을 복구 실행으로 표시하지 않는다.
- 11–12: 교체되는 인스턴스와 별도 보관 volume, 앱 경로와 관측 경로, 받은 증거와 미확인 경계를 분리한다. 낮은 CPU·빈 화면·상관관계에서 근본 원인을 만들어내지 않는다.
- 각 번호 장의 예측/확인 문제·출처·모델 한계가 존재한다. 모든실험은 고정 합성 자료이며 개인정보/실제서비스 입력이나 외부 전송은 추가하지 않았다. 단위와 계산·상태는 기존 공유 순수 모델을 사용한다.

## 선택 실습

`examples/observability/README.md`는 모델 CLI와 실제 제품 스택 실습 설계를 분리한다. `replay.mjs`는 같은 앱 모델을 import해 실패 경계/보관/누락/한정된 진단을 assertion으로 대조한다. Node v24.19.0에서 실행해 `synthetic checks passed`를 확인했다. 설치·네트워크·파일 쓰기가 없고 별도 정리 대상도 없다. 실제 제품 버전/tag/digest는 미선정·미검증으로 명시했으며 가짜 고정값이나 실행 가능한 운영 설정을 넣지 않았다.
