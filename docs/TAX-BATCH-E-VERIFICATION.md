## E의 선행 로컬 검증 — 앞선 배치 게시와 별도

D의 독립 준비 후보 `fe13e3f25d701faa2db179dac388ba0740cbc2e7` 위에 09 증여와 상속·10 공제·감면·세액공제를 준비했다. 공개 후보는 소개·01–10, 읽음 분모 10이다. 11–12의 활성 링크·본문·모델 함수는 아직 등록하지 않는다. 동시 DB·Kubernetes·주거 통합 전 기준이므로 이 기록은 최종 통합본의 검사 수나 E 게시 증거가 아니다.

- 증여는 가상 수증자 한 명, 상속은 가상 상속재산 전체의 출발 묶음이라는 경계를 다르게 표시한다. 평가 재산·이전 금액·공제의 같은 눈금과 계산 순서를 비교하며, 미확인이면 계산과 마지막 프레임을 `null`/보류로 남긴다. 0으로 채워 세금 없음으로 오해시키지 않는다.
- 소득공제는 과세표준, 세액공제는 산출세액 다음에 작동한다. 세 경로의 0–140 세액 눈금을 유지하며 가상 비환급 공제의 미사용액과 0 바닥을 명시한다. 실제 공제 적격·한도·감면·이월 규칙은 확정하지 않는다.
- 두 이전 유형의 0·소수·상한, 합산 상한, 공제 초과, 프레임/장부 일치, boolean 외 확인 상태 거부와 모든 금액 필드의 음수·비유한값·문자열·null 거부를 검사했다. 공제 비교는 구간 경계의 바로 전후 소수·0·100만과 공제액 0·초과에 대해 동일 누진 모형·감소액·반복 결정성을 검사한다.
- B의 직접 그림 검토에서 예측 이유가 초기 숫자를 유지하는 문제를 확인한 뒤 전체 예측 패널을 재검토했다. 04와 10의 이유가 현재 모델에서 선납/결정/정산 차액 또는 과세 바탕/공제액/세액 감소를 읽도록 고쳤다. 브라우저 검사도 이유를 펼친 상태로 값을 바꿔 그림·표와 대조한다. 이 E 후보에는 해당 수정이 포함되며 E의 hosted 화면 확인은 아직 하지 않았다.
- 수정 포함 `npm test`: 808개 통과, 실패 0. TypeScript·Vite production 빌드와 `git diff --check` 통과. 기존 큰 번들 경고는 남는다.
- 평가·합산·공제의 실제 법령 조건, 신고 여부와 과세표준 0의 차이, 공제의 위치와 혜택 확정의 차이를 본문·반례·이유 있는 확인 문제로 설명한다. 공식 자료와 사용 범위·확인일은 장별 출처 절에 있다.

최신 main 보존 통합, 선택한 suite의 production·직접 PNG 검토, main·Pages·실제 게시 바이트 대조는 E 차례에 실행한다. 이 선행 원고 검증을 앞선 배치나 E의 게시 완료로 보고하지 않는다.
