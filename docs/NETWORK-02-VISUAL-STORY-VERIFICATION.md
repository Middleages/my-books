# 네트워크 02장: 설명 장면 재보강 검증

작성일: 2026-10-18 (KST)
기준 main: `2c00370` (쿠버네티스 G 배포·통합 기록까지 포함).
범위: 네트워크 02장의 본문 내 비트 그림, 주소 띠, 전달 경로와 관련 작성 기준.

## 구현

- `AddressPrimer`: /16·/24·/25의 네트워크/호스트 비트를 색·숫자·범례로 구분한다.
  마스크와 호스트 비트를 0으로 만든 네트워크 주소를 같은 모델에서 계산한다.
- `addressSpace`: 기존 `addressFrames`의 로컬/원격·성공/중단 판정을 재사용한다.
  /24·/25는 동일한 256개 주소 구간이며 /25의 경계는 .128이다. /16의 65,536개
  구간으로 전환할 때 범위와 눈금 변화(256배)를 명시한다. 주소 개수는 호스트 수가 아니다.
- 띠 밖의 목적지(192.168.20.20)는 /24·/25의 띠 안에 잘못 그리지 않고 별도로 표시한다.
- PC·라우터의 형태, LAN 영역, 활성 구간과 패킷 이동을 표현한다. 최종 목적지 IP와
  다음 홉을 분리한다. NAT·ARP·정책 라우팅 등을 새로 재현하지 않는다.
- 모바일 경로도는 SVG 아이콘과 HTML 라벨로 재배치해 전체 축소로 글자가 작아지는 문제를 피한다.
- 재생·정지·이전/다음 단계·다시 보기·초기화·예측·정적 전체 단계를 보존한다.
  초기 목적지는 .150으로 두어 /24와 /25만 전환해도 차이를 볼 수 있다.
- 기존 URL·chapter id·readId·localStorage 키와 미지의 읽음 ID를 보존한다.
  다른 교재·카탈로그·홈·공유 경로 컴포넌트는 변경하지 않는다.

## 검증

- 신규 테스트를 먼저 실행해 미구현 실패를 확인한 후 모델을 구현했다.
- `npm test`: **255개 통과**. /25 분할·PC 위치 불변·띠 밖 목적지·/16 범위·비트/마스크/
  네트워크 일치·기존 경로 판정 일치를 신규 3개 테스트로 확인했다.
- `npm run build`: TypeScript 및 Vite production 빌드 통과.
  기존 전체 번들 500kB 경고는 유지되며 이번 범위에서 번들 구조를 바꾸지 않았다.
- 로컬 Chromium production 렌더: 1440×1000, 390×1000, 320×1000.
  캡처를 직접 열어 비트 그림·분할 띠·PC/라우터 형태·모바일 라벨을 확인했다.
- /24 직접 전달, /25 게이트웨이 경유, 잘못된 다음 홉 중단, 띠 밖 목적지,
  /16 전환, 조건 변경 초기화, 재생 중 실제 좌표 변화와 정지 후 단계 유지 확인.
- prefix 버튼의 키보드 Enter, 정적 단계 펼침, reduced-motion의 이동 효과 없음 확인.
- 기존 `parallel`·알 수 없는 읽음 ID를 주입하고 02장 읽음을 추가해 새로고침 후 함께 유지됨을 확인.
- 문단 중첩·문서 가로 넘침·페이지/콘솔 오류 없음.
- `git diff --check` 통과.

production 빌드를 확인했다. 일회성 QA 스크립트·캡처·브라우저는 앱 의존성이나 저장소에 추가하지 않았다.

## 근거와 한계

RFC 4632 §3.1의 prefix/마스크 및 RFC 1122 §3.3.1의 로컬/원격 판단을 다시 대조했다.
기존 본문·출처·가정은 보존한다. 참고 교재의 문장·도해·코드를 복제하지 않았다.

실제 패킷 전송·물리 장비·라우터 설정을 검증한 것이 아니다. 주소 띠는 주소 공간이며
실제 건물의 거리나 LAN의 물리적 크기가 아니다. 경로도는 모델의 LAN 배치를 함께 바꾼
가상 사례로, prefix만 바꿔 실제 케이블 연결까지 생기는 것으로 해석하면 안 된다.
실제 모바일 Safari·터치 기기는 미검증이다. 다른 장 전체의 시각 완성도를 재판정하지 않았다.
