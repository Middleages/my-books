작성: 2026-10-20 KST. 상태: **계획안, 구현·검증·게시 전**.
상위 계획: [돈·경제 시리즈](MONEY-TEXTBOOK-PLAN.md). 공통 규칙: [AGENTS](../AGENTS.md), [콘텐츠 작성 기준](CONTENT-AUTHORING.md), [홈 정보 구조](HOME-INFORMATION-ARCHITECTURE.md).
선행 교재 상태는 착수 시 최신 main과 각 검증 문서에서 재확인한다. 보험 4권의 진행 중 변경을 보존한다.

## 목적과 경계

비전공 성인이 “돈이 벌리고·소비되고·보유되고·이전될 때 어떤 과세 사건이 생기며, 과세표준·세율·공제·기납부액이 최종 납부액과 어떻게 연결되는가?”를 설명하도록 한다. 한국 생활 사례를 쓰되 **교육용 가상 계산과 실제 한국 제도**를 명시적으로 구분한다. 특정인의 세금 신고·절세 추천·법률 자문·실제 세액 자동 판정은 범위 밖이다. 실제 계좌·급여·주민번호를 입력받지 않는다.

1권의 가계 현금흐름, 2권의 정부 재정, 3권의 투자 총수익, 4권의 보험 보장과 연결한다. 투자·보험의 상품 설명과 세법 상세를 중복 집필하지 않는다.

## 시각 장면 공통 규칙

각 장은 **독자가 눈으로 발견할 관계 → 형태·색·배치·움직임 → 조작 전후 변화 → 동일 순수 모델 프레임 → 정적 대안**을 구현 전에 적는다. 숫자 카드나 입력 폼만으로 장면을 대체하지 않는다. 개념 옆에 도해·짧은 설명·예측·조작·해석을 둔다. 색 외 라벨/형태를 사용하고 축·단위·시점·범례를 붙인다. 데스크톱과 390/320px 모바일 재배치, 키보드/포커스, 재생·정지·단계·초기화, reduced-motion, 전체 정적 표를 제공한다. 그림·수치·그래프·표·판정은 동일한 순수 계산 모델을 읽고 표시 반올림으로 판정하지 않는다.

## 모델 계층과 가정

- **원리 모델**: 임의의 비음수 과세표준, 정렬된 구간·세율, 공제·기납부액을 받는 UI 독립 계산. 금액의 단위와 반올림 규칙을 명시. 세액은 음수가 되지 않도록 세액공제 처리 조건을 정의하고 환급/추가납부를 별도로 표시한다.
- **제도 모델**: 국가·과세연도·소득/거래 유형·납세자 조건·시행/경과 규정·근거 URL을 포함하는 버전형 자료. 공식 원문 확인 전에는 실제 세율표나 공제한도를 코드에 넣지 않는다. 교육용 가상 세율표는 ‘한국 현행 세율 아님’을 가까이에 표시한다.
- **불확실성**: 제도 미확인/적용 대상 불명/정보 부족이면 결과를 단정하지 않고 확인 질문으로 남긴다. 금액0, 과세표준0, 경계값, 면세·비과세, 공제 초과, 환급, 반복 실행, 거액과 비정상 입력을 검증한다.
- **A 기본 가상 사례**: 한 사람이 급여를 받고 소비·저축·자산이전하는 사건 카드. 과세 사건의 종류를 보여주되 각 카드의 세금 확정 여부는 조건부로 표현. 02는 가상 과세표준 0–100 단위 10%, 100–300 단위 20%, 300 초과 30%로 구간별 누적 세액을 시각화한다. 예: 과세표준 400이면 10+40+30=80, 평균 20%, 마지막 구간 한계 30%. 현실 한국 세율 아님. 경계 0/100/300/400 및 구간별 합 보존을 테스트한다.
- **B**: 가상 총급여와 공제/원천징수액을 별도 입력·장부로 표현. 연말정산 차액=결정세액−기납부세액; 양수 추가납부, 음수 환급(교육용 정의). 원천징수와 4대보험료를 세금으로 합치지 않는다.
- **C**: 부가가치세는 교육용 공급단계와 매입/매출 세액을 별도 장부로; 면세·영세율을 동일시하지 않는다. 투자 소득은 원천/실현/계좌별 과세 조건을 확인 전까지 가상 분류로만 다룬다.
- **D**: 실제 ISA·연금 세제는 기준연도·가입자·상품·인출 조건 확인 후에만 수치 적용. 부동산은 취득/보유/양도 과세 사건을 분리하며 거래세와 소득세를 섞지 않는다.
- **E**: 증여·상속의 시점·평가·공제 조건을 가상 사례로; 소득공제는 과세표준을, 세액공제는 계산된 세액을 바꾸는 위치를 구분하되 실제 제한·환급 가능 여부를 제도별로 확인한다.
- **F**: 사건 발생일·귀속기간·신고/납부일·환급일의 구분과 현금흐름을 같은 시간축에 표시. 가상 문서의 확정 사실·가정·미확인 항목을 색 외 기호로도 구분한다.

- 국세청 https://www.nts.go.kr/ : 소득세·연말정산·원천징수·금융소득·상속/증여·부가가치세
- 국가법령정보센터 https://www.law.go.kr/ : 소득세법·법인세법·부가가치세법·상속세 및 증여세법·조세특례제한법과 시행령
- 위택스 https://www.wetax.go.kr/ : 지방세·취득/재산 관련 항목
- 국세청 홈택스 https://www.hometax.go.kr/ : 실제 신고 서식과 항목 확인. 실제 개인정보 입력 없이 가상 예시만 사용
- 금융위원회 https://www.fsc.go.kr/ : 금융계좌 제도 안내. 발표·시행·예정 구분

## 구현 구조·배치 게이트

본문 `src/content/tax/*.mdx`, UI `src/components/tax/`, 모델 `src/simulations/tax/`; 기존 카탈로그·표지·테스트 패턴을 재사용한다. A는 소개·01·02만, 이후 B(03–04), C(05–06), D(07–08), E(09–10), F(11–12와 전체 편집) 순서. 미구현 장을 공개하지 않는다.

각 배치: 최신 main과 병행 작업·검증 기록 확인 → 공식 근거 확인 → 모델/테스트 → 장면/MDX → 독립 검토 → `npm test`, `npm run build`, `git diff --check` → 실제 production Chromium 1440/390/320 및 중간폭·키보드·reduced-motion·정적 표·콘솔·링크·읽음 회귀 → PNG 직접 확인 → main 통합 → Actions/Pages/게시 자산 대조. 미실행 항목은 통과로 기록하지 않는다. 실제 모바일 기기·Safari/Firefox·스크린리더 음성·학습효과는 별도 검증 전 미검증.

계획 문서 작성 자체는 장 구현·브라우저 검증·Pages 게시 완료를 의미하지 않는다.

## 2026-10-20 검증 범위 조정

사용자의 추가 지시에 따라 B–E는 매번 모든 기존 책의 전체 브라우저 회귀를 반복하지 않는다. 전체 단위 테스트·TypeScript·production 빌드는 유지하고, 변경한 세금 장과 같은 책의 관련 상호작용, 공용 홈·권차·링크·읽음 상태의 짧은 회귀를 production과 실제 게시 환경에서 검사한다. 선택한 검사의 경계값·키보드·reduced-motion·정적 표·정확한 자산 바이트 대조·PNG 직접 검토는 줄이지 않는다. 공용 컴포넌트나 다른 책도 영향을 받으면 해당 범위를 추가한다. F의 전체권 마무리에서는 넓은 브라우저 회귀를 다시 실행한다. 이전 기록의 실제 검사 범위·결과는 그대로 보존하며, 실행하지 않은 다른 책 전체 검사를 통과했다고 적지 않는다.
