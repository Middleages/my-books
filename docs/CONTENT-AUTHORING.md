# 교과서 콘텐츠 작성 기준

전역 원칙은 루트 [AGENTS.md](../AGENTS.md)를 따른다. 이 문서는 본문·컴포넌트 작성의 상세 기준과 예시를 제공한다.

적용일: 2026-10-17. 신규 본문은 **MDX**, 실험 UI는 **React/TypeScript**, 판정·계산은
별도 모델 파일로 작성한다. 장 수보다 본문 수정의 편의성을 기준으로 도입했다.

## 시각 학습 원칙 — 2026-10-17 개정

사용자의 최신 요청에 따라 신규 콘텐츠에는 **인터랙티브 시뮬레이션·설명용 애니메이션·그림을
적극적으로 사용한다.** 이전의 ‘필요한 곳에서만 제한적으로 실험을 추가’하던 방향보다
시각 설명의 비중을 높인다. 기존 배포 장을 이번 결정만으로 일괄 재작성하지는 않는다.

본문을 먼저 길게 쓰고 마지막에 실험 하나를 붙이기보다, 핵심 개념을 어떤 장면으로
보여 줄지 함께 설계한다. 그림을 먼저 보고 짧은 설명으로 의미를 확인한 뒤 직접 조작하고
실제 사례에 적용하는 구성도 적극 활용한다.

| 독자가 이해할 것 | 우선 고려할 형식 |
| --- | --- |
| 구성·관계·부분과 전체 | 설명 그림, 관계도, 단면·분해 그림, 주석 있는 비교 그림 |
| 시간 순서·이동·누적·상태 변화 | 단계 애니메이션, 전후 비교, 재생·일시정지·한 단계 진행 |
| 조건을 바꾼 결과·원인과 결과 | 직접 조작하는 시뮬레이션, 시나리오 비교, 그래프·표의 동시 변화 |
| 정확한 값·최종 정리 | 수치 표, 직접 붙인 라벨, 요약 그림과 텍스트 |

- 각 신규 장에 핵심 개념을 설명하는 시각 자료를 계획한다. 조건 비교가 중요한 곳에는
  입력을 바꿀 수 있는 실험을 배치한다. 숫자 입력과 결과 카드만으로 시각 설명을 대신하지 않는다.
- 시각 자료마다 ‘어떤 질문에 답하는가 / 무엇이 무엇을 나타내는가 / 독자가 무엇을 바꿀 수 있는가’를 적는다.
- 움직임은 과정의 순서·방향·누적·변화를 설명한다. 중요한 변화 전후를 멈춰서 비교할 수 있게 한다.
- 글과 시각 자료는 서로 보완한다. 주요 숫자·단위·라벨·가정은 그림 가까이에 표시한다.
- 정확한 도형·수치·상태는 SVG/HTML/Canvas 등 수정 가능한 코드 기반 요소로 만든다.
  삽화가 개념 이해에 도움이 되면 별도 이미지도 활용하되, 계산 근거가 되는 라벨·값을 이미지에 고정하지 않는다.
- 모바일에서도 주요 그림과 변화가 먼저 보이도록 하고, 조작부를 가까이 둔다. 큰 그림을 단순 축소해
  글자를 못 읽게 만들지 않는다. 가로 화면·hover·드래그만으로 학습할 수 있게 하지 않는다.
- 재생·정지·다시 보기와 키보드 대안을 제공한다. reduced-motion에서는 정적 단계·전후 비교로
  같은 내용을 전달한다. 자동 재생을 기다려야만 핵심 내용을 알 수 있게 만들지 않는다.

시각 자료를 적극적으로 쓰되, 개수나 움직임의 양보다 **보고 이해하고 조작할 수 있는가**를 기준으로 검토한다.

## 작성 위치와 역할

- `src/content/<bookId>/<Chapter>.mdx`: 설명·제목·문단·목록·표·출처와 실험 배치.
- `src/components/<bookId>/`: 상태·입력·단계 진행·결과 표시 등 상호작용.
- `src/simulations/<bookId>/`: UI와 독립적인 판정/계산. 기존 `.mjs` 모델은 현재 테스트 체계를 유지한다.
- `src/catalog.ts`: 장의 import와 id/readId/번호/제목. MDX import는 `.mdx` 확장자를 명시한다.

MDX 안에 복잡한 상태 처리나 판정 함수를 넣지 않는다. 기존 TSX 본문은 그대로
동작하며 대규모 일괄 전환은 하지 않는다. 본문을 크게 개정할 때 점진적으로 옮긴다.
04장 `Ports.mdx`를 시범 전환했고, 시각 보강 배치 A에서 08·09도
`Tls.mdx`·`Verify.mdx`로 전환했다. 배치 B에서는 01~03을
`Packets.mdx`·`Addressing.mdx`·`Routing.mdx`로 전환했다. 배치 D2에서는 07도 `Http.mdx`로 전환했다.
**이후 추가하는 본문은 MDX를 기본으로 사용한다.**

```mdx
## 실제 상황에 적용

관측 위치와 다음 확인 항목을 설명한다.

<Check question="무엇까지 알 수 있나요?" children="이 관찰이 뒷받침하는 범위까지만 알 수 있습니다." />

<Sources items={[["공식 근거", "https://example.org/spec"]]} />

</section>
```

JSX 컨테이너 안에서 Markdown을 쓸 때는 여는/닫는 태그와 본문 사이에 빈 줄을 둔다.
`Check`는 내부에 문단을 만들므로 짧은 답은 위처럼 `children` 문자열로 전달해
문단 중첩을 피한다. 코드 블록은 fenced code block을 사용한다. 주의 상자·학습 목표는
기존 `note`, `learning-goals` 클래스를 사용하는 작은 JSX 컨테이너로 감싼다.

## 빌드와 신뢰 경계

Vite에 `@mdx-js/rollup`과 `remark-gfm`을 추가했다. GFM 표를 지원하고,
`@types/mdx`로 TS의 MDX import 타입을 제공한다. Next.js나 사이트 구조 변경은 없다.
빌드 시 저장소 안의 신뢰한 MDX만 컴파일한다. 사용자 입력·원격 문서를 실행 가능한
MDX로 동적 평가하지 않는다. TypeScript 검사는 React/model 코드를, Vite 빌드는
MDX 문법과 import를 검사한다. MDX 내부의 모든 컴포넌트 prop이 TS로 완전히
검사된다고 가정하지 않고 실제 렌더와 조작도 검증한다.

## 전환/추가 완료 조건

1. 기존 URL, chapter id, readId, localStorage 키를 보존한다.
2. 학습 목표를 제시하고 그림과 짧은 설명 → 과정 관찰 → 예측·직접 조작 → 결과 해석·실제 적용 → 확인 문제·출처 흐름을 유지한다.
3. 표·코드·링크·퀴즈·실험이 렌더링되고 예측·초기화가 동작해야 한다.
4. `npm test`, `npm run build`를 통과한다.
5. 데스크톱·모바일 폭에서 가로 넘침·줄바꿈·포커스·콘솔 오류를 확인한다.
6. 읽음 표시 후 새로고침과 기존 장의 링크·실험을 회귀 확인한다.
7. 핵심 개념의 그림·애니메이션·실험이 본문 흐름 안에서 의미 있게 작동하며,
   모바일·키보드·일시정지·초기화·reduced-motion에서도 같은 설명을 전달하는지 확인한다.

참고: https://mdxjs.com/packages/rollup/ · https://mdxjs.com/docs/getting-started/


MDX의 `<p>` 안에 줄바꿈으로 일반 텍스트를 쓰면 Markdown이 또 다른 문단을 만들어
`<p><p>…</p></p>`가 될 수 있습니다. 도입 문장은 `<p className="lead">짧은 문장</p>`처럼
한 줄에 쓰거나 JSX 문자열 표현식을 사용합니다. 빌드 성공만으로 HTML 중첩까지 검증되지 않으므로
개발 모드의 React 콘솔 경고도 확인합니다.

04장 구매력 사례: `money/Inflation.mdx`와 `InflationLab.tsx`, `simulations/money/inflation.mjs`.
동일 연도 프레임을 그림·가격표·수량·그래프·표에 재사용하고, 명목/실질은 기준 시점과 단위를 함께 적습니다.
공식 교육자료의 단순 근사와 자체 모델의 정확식을 구분하며, 출처 확인일은 장별로 명시합니다.

01~03 시각 보강 사례: `network/foundation-visual.mjs`가 기존 기초 모델을 관찰 프레임으로
확장하고 `FoundationScene.tsx`의 경로·주소 전후·정적 단계가 같은 프레임을 읽습니다.
포맷터가 `<p>`의 텍스트를 여러 줄로 바꿀 수 있으므로, 직접 쓴 문단 태그에는
`<p className="model-note">{"출처 확인 문장"}</p>`처럼 JSX 문자열을 쓰면 중첩을 예방할 수 있습니다.


05장 이자 사례: `money/Interest.mdx`와 `InterestPrimer.tsx`·`InterestLab.tsx`,
`simulations/money/interest.mjs`·`interest.d.mts`. 관계 그림과 직접 조작을 같은 모델로 계산하며
월중 단계와 월말 확정 값을 구분합니다. 구성 막대의 라벨은 모바일에서 SVG와 함께 축소되지 않도록
HTML로 표시합니다. 원금·납입·수익·비용의 보존 관계를 모든 관찰 단계에서 검사합니다.


06장 목표 시점 사례: `money/Savings.mdx`, `SavingsVisuals.tsx`·`SavingsLab.tsx`,
`simulations/money/savings.mjs`·`savings.d.mts`. 같은 준비금에서 사용 가능 날짜만 바꾼 비교 그림과
월초 풀림/월말 적립/목표 지출의 실제 상태를 연결합니다. 목표일의 지출 직전 판정 기록을
이후 잔액과 분리해 표시하고, 뒤늦게 생긴 돈으로 지난 목표일의 판정을 바꾸지 않습니다.

04~06 시각 보강 사례: `ConnectionVisuals.tsx`·`TransportVisuals.tsx`와
`connection-visual.mjs`. DNS는 가장 가까운 유효 캐시와 남은 TTL 전달을, TCP는 수신 다음 기대 번호와
송신자가 실제 확인한 ACK를 분리합니다. 05·06도 MDX로 옮겼으며 기존 문장·표·퀴즈·관찰 명령·출처를
보존했습니다. 모바일에서 경로 방향이 달라지면 이동과 화살표도 같은 방향으로 재배치합니다.


07·12 시각 보강 사례: `BrowserVisuals.tsx`와 `browser-visual.mjs`.
URL 구성·현재 구간·HTTP 상태, OPTIONS·본 요청 도착·서버 처리·JS 읽기를 같은 프레임으로 표시합니다.
OPTIONS 응답과 본 응답의 공유 정책은 별도로 바꿔 비교하며 기존 `corsResult`를 두 검사에 재사용합니다.
모바일에서 앱 연결이 DNS 서버를 통과하는 것으로 보이지 않도록 앱 구간은 별도 바깥 선으로 배치합니다.


홈의 책 분류·목차 배치·진행률 표시 규칙은 [홈 정보 구조 결정](HOME-INFORMATION-ARCHITECTURE.md)을 따른다. 새 책은 카탈로그에 분야(`categoryId`)와 분야별 권장 학습 순서인 권차(`volume`, 양의 정수)를 명시한다. 같은 분야의 권차는 중복하지 않으며 제목·배열 위치로 추론하거나 기존 권차를 재번호화하지 않는다. 홈 카드·책 소개의 권차는 공통 메타데이터를 사용하고, 장 목록은 책 안의 목차에서 제공한다.


07장 월 부담 사례: `money/Credit.mdx`, `CreditVisuals.tsx`·`CreditLab.tsx`,
`simulations/money/credit.mjs`·`credit.d.mts`. 신용 심사의 질문과 생활 예산의 질문을
나누며 임의 신용점수·대출 승인 결과를 만들지 않습니다. 월수입·생활비·기존 납입·신규
원금·이자·남기려는 현금을 구분하고, 예비여유는 출금 비용으로 중복 차감하지 않습니다.
금리·수입 경로의 변경 외 비교 조건을 맞추며, ‘예비여유 부족’과 ‘월수입 자체의 부족’을
같은 모델이 구분합니다. 예정 상환 후 잔액은 실제 납부·연체를 실행한 잔액과 구분해 표시합니다.


08장 상환 일정 사례: `money/Repayment.mdx`, `RepaymentLab.tsx`·`RepaymentVisuals.tsx`,
`simulations/money/repayment.mjs`·`repayment.d.mts`. 세 방식의 같은 월/단계에서
예정 납입 구성과 현재 원금 잔액·누적 납입을 구분합니다. 전체 그래프·표는 월말 예정 값이며
월중 현재 상태를 가장하지 않습니다. 마지막 납입 뒤 확인 단계에서 원금을 다시 차감하지 않습니다.
소수 원을 유지한 계산과 표시 반올림을 분리하고 0금리·마지막 회차·누적 보존 관계를 검증합니다.
모바일 그래프는 별도 좌표 폭으로 축과 글자 크기를 유지하며 숫자·단계·세로 카드·전체 표를 함께 제공합니다.


### 돈 09장의 위험 대비 비교 기준

집중·분산은 같은 최초 금액과 기간별 충격을 적용한다. 보험 비교는 같은 출발 예산·투자 노출에서 보험료를 현금으로 지불하며 보험금을 무료 수익으로 더하지 않는다. 지급 대상과 실제 도착 현금, 투자 평가액과 매각 가능액, 미충당 지출을 구분한다. 남은 자산만으로 순자산·개인 안전성을 판정하지 않는다. 실험 가까이에 자기부담금·한도·제외·지급 지연과 단순화한 계약 가정을 적는다. 모델 프레임의 `자산 + 충당액 = 최초 자금 − 보험료 + 평가손익 + 도착 보험금` 관계를 테스트한다.


### 돈 10장의 통합 계획 기준

`plan.mjs`는 08의 상환 모델을 재사용하고 계획의 현금 잔액과 실제 납부 결과를 구분한다. 음수를 자동 차입으로 해석하지 않는다. 목표 이체는 총액 보존, 소비는 한 번만 차감한다. 월중 그림과 월말 전체 경로의 시점을 명시하고 비교 그래프에는 같은 눈금을 적용한다. 현금 부족과 목표 적립 부족은 다른 판정이며 과거 실패를 미래 수입으로 지우지 않는다. 긴 표에는 이름과 키보드 포커스를 제공한다.

### 범위 표기와 스크롤 표의 실제 렌더

같은 문단에서 `01~10`, `01~03`처럼 물결표 범위를 반복하면 GFM이 그 사이를 취소선으로 해석할 수 있다. `01–10` 같은 범위 표기를 사용하고 실제 DOM에 의도하지 않은 `del`이 없는지 확인한다. 가로 스크롤이 필요한 표 영역에는 이름·키보드 포커스·보이는 포커스를 제공하고, 모바일에서 표 열에 키보드로 접근할 수 있는지 확인한다.

기호만 강조하거나 닫는 괄호 뒤에 조사가 붙으면 `**+**는`, `**6%포인트(6%p)**입니다`가 그대로 표시될 수 있다. 이 경우 `<strong>+</strong>는`처럼 명시적인 요소를 쓰고 본문에 Markdown 별표가 남지 않는지 확인한다.

## 설명력이 먼저인 시각 장면 — 2026-10-18 확정

사용자는 네트워크 02장 시범 보강을 확인하고 기존보다 이해하기 좋아졌다는 의견과 함께
지침의 문서화를 요청했다. 다음 기준을 모든 교과서의 신규 작성·기존 장 보강에 적용한다.
이 결정만으로 기존 교재 전체의 재작성이나 검증 완료를 선언하지 않는다.
사용자 수용을 학습 효과에 대한 별도 실험·정량 검증 결과로 확대 해석하지 않는다.

### 1. 목표: 독자가 눈으로 발견할 관계

2D·3D·애니메이션 개수는 목표가 아니다. 독자가 장면을 본 뒤 설명할 수 있어야 할
관계·과정·차이를 먼저 정한다. 정적 그림으로 충분하면 정적 그림을 사용한다.
3D는 입체적 배치·단면·깊이 자체가 이해에 필요한 경우에 선택한다.

| 독자가 이해할 것 | 적합한 표현 | 눈으로 드러나야 할 것 |
| --- | --- | --- |
| 구성·역할 | 형태가 구별되는 대상과 직접 라벨 | 누가 무엇을 하는가 |
| 포함·범위·경계 | 영역·분할 띠·계층·단면 | 무엇이 어디에 속하며 경계가 어디인가 |
| 양·비율·누적 | 같은 눈금의 막대·높이·면적·그래프 | 무엇이 얼마나 늘거나 줄었는가 |
| 이동·처리 순서 | 경로와 재생 가능한 단계 | 무엇이 어디로 이동하고 언제 바뀌는가 |
| 조건에 따른 차이 | 조작·나란한 비교·전후 고정 장면 | 조건 하나가 어떤 결과를 바꾸는가 |

입력 폼과 결과 숫자, 긴 로그, 같은 모양의 상자 안에서 바뀌는 문장만으로
핵심 관계의 시각 설명을 대신하지 않는다. 보조 수치·정확한 표·텍스트 대안은 함께 제공한다.

### 2. 장면을 설계하는 순서

1. 독자의 질문을 한 문장으로 정한다.
2. 정답을 이해하려면 발견해야 할 관계를 적는다.
3. 그 관계를 나타낼 형태·위치·경계·크기·색·이동을 고른다.
4. 바꿀 조건과 유지할 조건, 조작 전후의 관찰 차이를 정한다.
5. 실제 모델의 상태·수치·판정과 그림의 각 요소를 연결한다.
6. 모바일·키보드·정지·움직임 줄이기에서도 같은 관계를 읽을 방법을 정한다.

장별 계획이나 구현 설명에는 아래 항목을 필요한 만큼 짧게 남긴다.
모든 장면에 별도 대형 계획 문서를 강제하지 않는다.

| 설계 항목 | 네트워크 02장 사례 |
| --- | --- |
| 질문 | 같은 두 IP인데 prefix에 따라 출구가 필요해질까? |
| 눈으로 발견할 관계 | 같은 256개 주소가 .128에서 나뉘면 A와 B가 다른 범위가 됨 |
| 시각 속성 | 비례 주소 띠·고정된 PC 위치·분할 경계·전달 경로 |
| 바꿀 조건 / 유지할 조건 | /24와 /25 / 출발지 .10·목적지 .150·표시 구간 |
| 관찰 차이 | 직접 전달 / 라우터 경유 |
| 데이터 근거 | 기존 addressFrames 판정과 addressSpace의 동일 주소 계산 |
| 가정·대안 | prefix에 맞춰 LAN 배치도 구성한 가상 사례·정적 단계 설명 |

초기 예시는 차이가 쉽게 드러나게 고른다. 불필요하게 많은 입력을 바꿔야만
핵심 차이를 발견하게 하지 않는다. 반례·실패 사례와 전체 초기화도 유지한다.

### 3. 그림·색·움직임의 역할

- PC·라우터처럼 역할이 다른 대상은 형태·라벨로도 구분한다. 단순한 네모가 관계를
  잘 나타내는 경우에는 사용할 수 있지만, 모든 대상을 동일한 텍스트 카드로 대체하지 않는다.
- 색은 네트워크·호스트, 출발지·목적지, 원금·이자처럼 의미 있는 차이에 사용한다.
  동일한 장면·비교 안에서는 같은 의미에 같은 색을 쓰고 범례·라벨을 붙인다.
  사이트의 파란 포인트 색이 학습 그림의 색 구성을 제한하지 않는다.
- 선·화살표·영역·크기·높이가 뜻하는 바를 밝힌다. 그림을 꾸미기 위해 수치 비례를
  왜곡하거나 실제 거리·시간·속도·성공 확률로 오해할 효과를 넣지 않는다.
- 비례 그림의 눈금·범위가 바뀌면 알린다. 그림 밖의 대상을 경계 안으로 임의 배치하지 않는다.
- 움직임은 순서·이동·분할·누적·상태 변화를 보여 준다. 의미 없는 반복 운동이나
  모든 요소의 등장 효과를 학습용 애니메이션으로 계산하지 않는다.
- 전후 상태를 멈춰서 비교할 수 있어야 한다. 재생을 기다리거나 장면을 기억해야만
  관계를 파악할 수 있게 하지 않는다. 시작·끝의 고정 그림도 의미를 전달해야 한다.
- 설명하는 개념 가까이에 장면을 배치한다. 도해·짧은 설명·과정 관찰·조작을 본문에
  연결하며 장 끝에 실험을 몰아넣지 않는다. 그림만으로 오해할 조건은 가까이에 적는다.

### 4. 모바일과 접근성도 같은 설명을 전달하기

- 데스크톱 그림을 통째로 축소해 주요 글자를 못 읽게 만들지 않는다. 방향·그룹·패널을
  재배치하고, 필요하면 SVG 아이콘과 HTML 주소·설명을 분리한다.
- 모바일에서 경로가 세로로 바뀌면 화살표와 패킷 이동도 같은 방향으로 바꾼다.
- 색·hover·드래그만으로 구분하거나 조작하지 않는다. 형태·라벨·버튼·키보드 대안을 제공한다.
- reduced-motion에서는 이동을 없애거나 줄여도 경계·현재 위치·전후 차이·결과 해설이 남아야 한다.
- 자동 재생 없이도 첫 화면의 구성과 핵심 관계를 읽을 수 있게 한다. 정지·초기화는
  타이머와 이동 효과까지 일관되게 처리한다.

### 5. 완료 점검: 기능과 설명력을 나누어 확인하기

모델 테스트·빌드·회귀 검증은 기존 기준을 따른다. 그와 별도로 데스크톱·모바일 캡처를
직접 열어 다음을 점검하고 장별 검증 기록에 실제 관찰과 미검증 범위를 남긴다.

- [ ] 첫 화면에서 대상의 역할과 그림의 구도를 알 수 있는가?
- [ ] 문장·숫자를 읽는 것 외에도 핵심 관계가 형태·위치·크기·경계 등으로 드러나는가?
- [ ] 중요한 조건을 바꾸면 무엇이 유지되고 무엇이 달라지는지 눈으로 비교할 수 있는가?
- [ ] 색·범례·화살표·눈금·모델 판정이 서로 일치하는가?
- [ ] 과정에 필요한 실제 이동·상태 변화가 보이며, 정지한 상태에서도 해석할 수 있는가?
- [ ] 모바일 주요 라벨이 읽히고 키보드·움직임 줄이기·정적 대안도 같은 내용을 전달하는가?
- [ ] 그림에서 알 수 있는 것과 추가 확인해야 할 것, 교육 모델의 가정이 구분되는가?

체크한 근거가 없으면 '시각 보강 완료'라는 이름이나 테스트 개수만으로 통과 처리하지 않는다.
사용자 피드백과 기능 검증, 작성자의 시각 검토는 구분해서 기록한다.

### 6. 적용 예시와 기준 사례

| 개념 | 권장 장면의 예 | 주의할 오해 |
| --- | --- | --- |
| IP·서브넷 | 비트 역할·주소 띠 분할·패킷 경로 | 주소 범위가 같으면 물리 연결도 보장됨 |
| NAT | 통과 전후 주소·포트와 대응표를 연결 | NAT와 라우팅·방화벽을 같은 기능으로 봄 |
| 인증서 | 서버 목록·발급 관계·클라이언트 신뢰 기준을 분리 | 서버가 보낸 루트를 자동으로 신뢰함 |
| 대출 상환 | 납입금의 원금/이자 구성과 줄어드는 잔액 | 납입금 전부가 원금을 줄임 |
| 쿠버네티스 | 원하는/현재 개수와 실제 Pod 교체 과정을 연결 | 새 Pod를 기존 Pod의 부활로 봄 |

이는 설계 예시이며 다른 장에 이미 구현·검증됐다는 뜻이 아니다.
기준 사례는 네트워크 02장의 `AddressPrimer`(32비트 역할),
`AddressSpaceDiagram`(비례 주소 띠), `AddressPath`(PC/라우터와 유지되는 목적지 IP)다.
주소 띠·색상·카드 배치를 모든 주제에 복제하지 않고, 해당 개념에 맞는 표현을 선택한다.

구현·검증·배포 근거와 한계는 [02장 설명 장면 검증](NETWORK-02-VISUAL-STORY-VERIFICATION.md)을 참조한다.
